# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`simcardemsx` (distribution name `simcardemsx`, import name `simcardemsx`) is a next-generation cardiac electro-mechanics solver built on FEniCSx. It couples an electrophysiology (EP) solver from [fenicsx-beat](https://github.com/finsberg/fenicsx-beat) (`beat`) with a mechanics solver from [fenicsx-pulse](https://github.com/finsberg/fenicsx-pulse) (`pulse`), driven by cellular ODE models that are code-generated from `.ode` files via [gotranx](https://github.com/finsberg/gotranx).

This package requires FEniCSx/dolfinx, which is not pip-installable on its own — it must come from the `ghcr.io/fenics/dolfinx/dolfinx` container image (see `.devcontainer/`). Assume dolfinx, mpi4py, petsc4py, ufl, and basix are already present in the environment rather than trying to pip install them.

`third-party/` contains local, untracked (gitignored) checkouts of sibling/dependency projects (`fenicsx-beat`, `fenicsx-pulse`, `crossbridge`, `gotranx`, `cardiac-geometriesx`) kept around for reference when reading their source. They are not part of this repo's history. They are maintained by the same people, so a change that belongs upstream is made as a PR against that project's own repo, not patched around here. `third-party/physcardems` is the exception: Jenny Wang's electromechanics stack, the one simcardemsx aims to let her replace. `numerical_experiments/rodero_05` and `tests/test_rodero_case.py` read its `cases/rodero_05` in place; the case data is never copied into this repo.

## Architecture

A simulation couples two independently-meshed physics solvers that exchange state every mechanics time step.

**1. Code generation from `.ode` files (`ode_model.generate_ode_code`)**

A single gotranx `.ode` file describes the full cellular model, with one component named `"mechanics"` (the active-stress state variables, e.g. `Zetas`/`Zetaw`/`XS`/`XW` for a Land model) and the rest being EP state. `generate_ode_code` splits it (`ode.get_component("mechanics")`, `ode - mechanics_comp`) and code-generates two Python modules into an output dir, both via gotranx's own stock generators — there is no custom code generator, printer or method-signature template in this package any more (`ode2mechanics.py`/`template.py` are gone):

- The EP remainder is compiled by `gotranx.cli.gotran2py.get_code` (generalized Rush-Larsen scheme) into `ep_model.py` — plain numpy code, consumed by `beat.odesolver.DolfinODESolver`.
- The `"mechanics"` component is compiled by `gotranx.cli.gotran2ufl.get_code`, the same GRL scheme, into `mechanics_model.py`. Its state update is **UFL expressions instead of numpy/math**, so it can be evaluated symbolically on the mechanics mesh — nothing here is hand-ported any more.
- Each call passes `missing_values=<other side>.missing_variables`, and each written module gets a `provides: dict[str, int]` dict appended after generation: the names its own `missing_values()` returns, by output index — i.e. what it hands to the *other* side. `load_ode_modules` generates and loads both, returning an `ODEModules(ep, mechanics)` pair; prefer it over calling `generate_ode_code` and loading only `ep_model` — deriving what crosses (§2, `transfer_plan.resolve`) needs both.
- `backends/` holds the **activation backends**, which is the main organising idea of the package. Each owns how active tension is produced *and* how it is coupled to mechanics, and each is a `pulse.ActiveModel` handed straight to `pulse.CardiacModel`. `backends/base.py` defines the `CoupledBackend` protocol, which is what `SimulationController` requires of a backend: read-only `missing` and `provides` (the name→index dicts of the generated activation module, §2), `quadrature_degree`, `inputs`/`outputs` (EP→backend before the step, backend→EP after it), `space`, `active_tension`, and the two calls `begin_step(t_n, dt)` (ms, the old time and the mechanics step) and `post_solve()`. The order is `begin_step`, then the mechanics solve, then `post_solve`, and **nothing is accepted before `post_solve`**: until then the stored states, `outputs` and `active_tension` are those of the last accepted step, so a step whose solve fails leaves them untouched. `GeneratedActivation` and `CrossbridgeSegregated` implement it, and it is `isinstance`-checkable (`runtime_checkable`). What crosses is derived from the EP module and the backend's `missing`/`provides` by `transfer_plan.resolve` and moved by a `TransferPlan` (§2), for both of them; `ZetaSplitUFL` does not implement it and is driven directly against `pulse`. The `Transfer` record (name + unit + state/monitor, since a bare name carries neither direction nor unit) remains in `base.py` as documentation of units. Nothing in `src` reads a `Transfer` record. `CrossbridgeSegregated`'s `wants_from_ep`/`gives_to_ep` are kept naming the same variables as its dicts only by `test_crossbridge_transfer_records_agree_with_its_dicts`. `ZetaSplitUFL`, which the controller does not drive, still declares its crossings with `Transfer` alone (`zeta_split.py`), and `test_backends.py` reads those. The unit conversions live and are tested inside each backend (ADR 0004, `.scratch/adr/`).
- `backends/generated.py` holds `GeneratedActivation`: the `mechanics` component, generated as UFL, stepped once per mechanics solve. `scheme="monolithic"` (the default) sets the component's `lmbda`/`dLambda` parameters from the *current* displacement, so `S(C)` is a UFL expression of `C` and Newton differentiates through the whole contraction model — whatever the `.ode` file contains, not just the two Land distortion states `ZetaSplitUFL` hand-coded. `scheme="segregated"` instead freezes `lmbda`/`dLambda` at the last converged step: the naive scheme, kept only as the non-convergent comparison. `scheme="stabilized"` is Regazzoni & Quarteroni's Eq. (19) on that segregated step: the same stored states, with `Ta_seg + Ka·(λ(u) − λ_n)` as the tension, through `pulse.StabilizedActiveStress`, `λ_n` being the frozen stretch. `Ka` is `ufl.diff` of the stepped tension with respect to the step's end stretch, taken at the frozen point, so it runs through both uses of that stretch: the length dependence, and the rate, which brings the 1/dt and the GRL factor κ. It is the discrete counterpart of R&Q's Eq. (44), which adds the length path to the rate path of Eq. (42). The term is O(dt), so the scheme stays consistent. It is defined for the `stretch` formulation only, and the constructor raises `ValueError` for `invariant`. `t`, `dt` and every parameter are `dolfinx.fem.Constant`s (`begin_step(t_n, dt)` sets the first two, and nothing else), read when the form is assembled — not Python floats — because pulse compiles the form once, when the `StaticProblem` or `DynamicProblem` is built, while `dt == 0`; a Python-float branch taken at that point is baked in forever (exactly the bug `ZetaSplitUFL`'s dt fix, below, corrects), and gotranx's UFL printer also emits `ufl.Or(x > a, x < b)`, which fails outright on a float `x`. States live on a quadrature space at the mechanics form's own `quadrature_degree` by default (an `element=("family", degree)` override exists, e.g. for comparison against DG1), so the stored states are exactly the ones the residual used. `active_tension` is a P1 `Function`, averaged from the quadrature tension via `averaging.make_averager`, always reported **in kPa** regardless of the model's own `tension_unit` (`ZetaSplitUFL` reports Pa, `CrossbridgeSegregated` kPa).
- **End-of-step evaluation (`evaluate_at_end_of_step`).** `pulse.DynamicProblem` (generalized-α) assembles its material, compressibility and viscous stress, its Robin/Neumann loads and its body force at the α_f point `α_f·u_n + (1 − α_f)·u_{n+1}` (defaults α_f 0.4, α_m 0.2); only the cavity constraint, `J − 1` and the circuit sit at the true end-of-step `self.u`. For `GeneratedActivation` the α_f point is a wrong model, not a less accurate one: the GRL step inside `S` would see a blend of two stretches and a stretch rate about `(1 − α_f)` times the true one, and `post_solve`, compiled against the `u_{n+1}` that `register()` receives, would then store different states from the ones the residual used. pulse's `ActiveModel.evaluate_at_end_of_step` class attribute (pulse ≥ 0.10, default `False`) fixes that for a model that sets it: `DynamicProblem._material_form` then assembles `model.S(C, C_dot=..., active=False)` at α_f and `model.active.S(C(u_{n+1}))` against the variation at `u_{n+1}`. `GeneratedActivation`, `ZetaSplitUFL` and `CrossbridgeSegregated` all set it `True`. It has no effect under `StaticProblem`, which has no α_f point. pulse reads it when it compiles the form, at problem construction, so setting it on an instance afterwards changes nothing; `conftest._dynamic_mechanics(end_of_step=False)` sets it *before* building the problem. This is the change that makes physcardems' `true_u_active` unnecessary. Its run scripts set `model.active` to `Passive()`, and its `ControlledCavityDynamicProblem` adds `true_u_active.S(C, dev=True)` at `self.u` by hand; `conftest._TrueUActive` keeps that form (without `dev`), as the independent reference of D1 and X6. The effect is not small: on D1's damped 1 cm element the α_f evaluation moves `mean(λ)` by up to 7.7e-3 and lowers peak `Ta` from 1.80 to 1.23 kPa.
- **`tension_scale`** (`GeneratedActivation(..., tension_scale=...)`, a `Function` or UFL expression, default `None`) multiplies `Ta` in `S` (before the stretch normalization and the conversion to Pa) and in the tension `post_solve` averages into `active_tension`, and, under `stabilized`, `Ka` alike (scaling one without the other would break the consistency of the stabilization), and nothing else. The states still advance, and everything crossing back to EP (λ, the `provides` outputs) is unscaled, so a masked region keeps its cellular dynamics and only stops pulling. `rodero_05` uses a DG0 mask (1 in the myocardium, 0 in the valve plugs) to take the active stress out of its plugs, and gate A2 uses a `Constant(0.0)` as its no-tension baseline. `active_tension` is a P1 average, so at a node shared by masked and unmasked cells it is a blend, not 0. When the mask matters, read `backend.tension_kPa` instead: the quadrature `Function` that `post_solve` writes and `active_tension` is averaged from, read-only, unaveraged, and exactly 0 wherever the mask is 0. `rodero_05` reads it for its min/max.
- **`stiffness_kPa`** is `Ka` of the last accepted step, in kPa per unit stretch, for every scheme: a read-only quadrature `Function` that `post_solve` overwrites in place, with `tension_scale` applied, so it is exactly 0 where the mask is 0. It is the derivative of the stepped tension through both the length dependence and the rate (its 1/dt), at the step's evaluation point: the converged λ(u) under `monolithic`, the frozen λ_n under `segregated` and `stabilized`, where it is the `Ka` the residual used. Under `stabilized`, `tension_kPa` is the monitor `Ta_seg` of the stored states, not the stress `Ta_seg + Ka·Δλ` the residual saw.
- **The stretch at rest.** `GeneratedActivation` starts `lmbda_prev` at 1, i.e. it assumes the mechanics starts in its reference configuration. A problem that starts deformed needs one of two starts, or the first step sees a stretch rate of `(λ(u_0) − 1)/dt`. One is `backend.reset_stretch()` after `register(u)`, then `controller.plan.backward()`, which `circulation_biv` does after its inflation. It sets `lmbda_prev`, the frozen `lmbda` and `outputs["lmbda"]` to λ(u) and the frozen `dLambda` to 0, so the first step sees no rate under any scheme; the states are untouched and nothing goes to EP until `plan.backward()`. It raises `RuntimeError` before `register`. The other is to accept one solve with `backend.dt == 0`, where the step is the identity: `plan.forward`, `problem.solve()`, `post_solve`, `plan.backward`, which is `rodero_05`'s unloaded solve.
- **`S` is the primary contract, not `strain_energy`.** pulse's `_material_form` (`StaticProblem`'s, and `DynamicProblem`'s, which for a flagged model calls `model.active.S` directly) assembles `model.S(C)` and never touches `strain_energy`; neither `GeneratedActivation` nor `ZetaSplitUFL` has a closed-form potential to differentiate (`Ta` depends on the stretch *rate* through states advanced by GRL), so both raise `NotImplementedError` from `strain_energy` rather than returning something plausible.
- `ZetaSplitUFL.Ta(lmbda)` is a **method** returning a UFL expression; the output `Function` is `active_tension`. Do not merge those names — a `Function` called with a float does not raise, it hangs in point evaluation.
- `backends/zeta_split.py` holds `ZetaSplitUFL`, the hand-ported Land model, now **deprecated** (`DeprecationWarning` at construction, naming `GeneratedActivation`) and kept only because physcardems imports it. Its `dt` used to be a Python float, baked into the compiled UFL form while `t == t_prev == 0`; it is now a UFL expression of `Constant`s, like `GeneratedActivation`'s, so its zeta states do see the current stretch inside Newton once the clock moves. Don't describe this backend as "monolithic-in-Newton by construction" any more — that phrasing predates the dt fix, and in any case `GeneratedActivation` now does the same for any `.ode` split, so it is no longer this backend's distinguishing feature.
- `backends/segregated.py` holds `CrossbridgeSegregated`, the Ca_i split, a `CoupledBackend` with `missing = {"cai": 0}` and `provides = {"J_TRPN": 0}`, so the controller drives it, with `outputs = {"J_TRPN", "lmbda"}` (`outputs["lmbda"]` is `lmbda_prev` itself, as for `GeneratedActivation`, so an EP Ca_i remainder that keeps `lmbda` as a parameter is sent λ; the shipped caisplit module has none, so nothing changes for it), for the Ca_i split only (`resolve` refuses the zeta split, naming `Zetas` and `Zetaw`).
  - **Why segregated.** Because crossbridge is NumPy it cannot be re-integrated inside Newton, so this interface is segregated — which is *not convergent* without stabilization once active stiffness exceeds passive stiffness (R&Q 2021). It therefore delegates its stress form to `pulse.StabilizedActiveStress`. The stabilization is `stabilized=True` by default. The slab example maps `--scheme stabilized` to it and `segregated` to `stabilized=False`, the non-convergent comparison, and there is no monolithic scheme for it.
  - **Trial and commit.** `begin_step(t_n, dt)` deep-copies the crossbridge model into a trial and advances *the trial* with the calcium in `inputs` (mM→µM), the accepted stretch λ_n (`lmbda_prev`, as `SL = λ_n·SL_ref`) and the shortening velocity `dSL = (λ_n − λ_{n−1})·SL_ref/dt`, then writes the trial's `Ta` and `Ka` (rescaled by `active_stiffness_to_mechanics`) into the Functions the stress reads. At `dt == 0` the trial is not advanced, which is the identity. `post_solve()` commits the trial, shifts λ_{n−1} := λ_n and sets λ_n := λ(u) from the converged displacement, then writes `J_TRPN`, `tension_kPa`, `stiffness_kPa` and the P1 `active_tension`. It raises `RuntimeError` if no `begin_step` is pending. Only `post_solve` and `reset_stretch()` write `lmbda_prev`, so the stretch the ODE was advanced with and the one the stabilization measures its increment `Ka·(λ(u) − λ_n)` from are the same object by construction (the invariant of ADR 0002, which the old `step()` kept by writing both in one place). The model, λ_n, λ_{n−1}, `tension_kPa`, `stiffness_kPa`, `active_tension` and `outputs` are therefore untouched by a failed step (gate X3). `step(t, dt)` survives as a deprecated alias of `begin_step` (`DeprecationWarning`).
  - **The stretch at rest.** A `dt == 0` step accepts `u` as the rest state: after it λ_{n−1} = λ_n = λ(u), so the next step sees no shortening velocity, as for `GeneratedActivation`. `reset_stretch()` does the same without a step (`RuntimeError` before `register`) and discards a pending `begin_step` trial, which was advanced with the old λ_n, so a fresh `begin_step` is needed and a stray `post_solve` raises, and a deformed start with neither starts the first step from λ = 1. Since `e334df3` that is a change from the old `step()`, which used λ(u_0).
  - **Space and evaluation.** `quadrature_degree=` puts the states, `inputs`, `outputs` and the stress's `Ta`/`Ka` on a scalar quadrature space at that degree, which must equal the mechanics form's (the controller checks, as for `GeneratedActivation`); without it they stay on DG1, which is what the direct-against-`pulse` tests use, and giving both `quadrature_degree` and `element` raises `ValueError`. `evaluate_at_end_of_step = True`, so it is evaluated at the true `u_{n+1}` under `DynamicProblem` (gate X6). It also exposes `mesh`, which the scheme-comparison `Recorder` reads.
  - **What it reports.** `tension_kPa` and `stiffness_kPa` are read-only Functions on `space` (DG1 by default, a quadrature space only with `quadrature_degree=`), written at `post_solve`, so they hold the accepted step's values and are not the `Ta_current`/`Ka_current` the stress reads between `begin_step` and `post_solve`, which hold the trial's. `active_tension` is a P1 average of `tension_kPa`, as for `GeneratedActivation`, in kPa.
  - **RDQ20MF needs crossbridge ≥ 0.3.3**, which `pyproject.toml` requires. Before 0.3.3, `RDQ20MF.advance_step(dt)` took one explicit-Euler RU step and advanced the crossbridges on every 40th call, so it was correct only at `dt = dt_RU` = 25 µs. At dt_mech 1 ms `Ta` stayed 0 for 40 ms and then overshot, and coupled to EP the calcium went negative and the run NaN. crossbridge 0.3.3 (PR #25) splits a step into sub-steps of at most `dt_RU`, as RDQ18 and the Land family already did.
- `units.py` holds the EP/crossbridge/mechanics conversions (ms↔s, mM↔µM, kPa, `J_TRPN`). None of these mismatches raises. The one that is not a plain scale factor is `active_stiffness_to_mechanics`: `Ka` is reported per unit of crossbridge's `Λ = SL/SL0` but consumed against the solver's `λ`, so it needs `× SL_ref/SL0`. With the default `SL_ref == SL0` the factor is 1, which is exactly why omitting it goes unnoticed.
- `RDQ18` defines no `SL0` (it uses `SL` directly in `Chi(SL)`), so `CrossbridgeSegregated` requires an explicit `SL_ref` for it rather than guessing one — a guess would silently move the model along its force-length curve.
- **Active-stress convention:** backends take a `formulation`. The default is `stretch`, the Regazzoni & Quarteroni normalization `P_a = Ta·F f0⊗f0/|F f0|`, under which `|P_a f0| = Ta` regardless of stretch. The historical simcardems form `invariant` (`P_a = Ta·F f0⊗f0`) is larger by a factor of λ and is retained only to reproduce pre-change results — results generated with it are not comparable to new ones. On a 1-element contraction the difference is ~31% in stress but only ~2.4% in peak shortening, since Holzapfel-Ogden stiffens exponentially; don't assume the discrepancy is negligible on other geometries.

- `zero_d.py` replaces the FEM mechanics with R&Q's 0D tissue model, so the same contraction models can be driven through all three coupling schemes (monolithic / segregated / stabilized) with no mesh. The monolithic run is a genuine reference solution — it root-finds the strain at which the ODE is advanced so the balance holds — and `tests/test_zero_d_coupling.py` uses it to assert the claim the whole design rests on: the naive scheme's error *grows* under refinement while the stabilized one converges at first order. **It works in seconds and pascals**, following the paper, unlike the rest of the package which uses ms.
- The instability only appears in the **quasistatic** regime (`M = sigma = 0`) and needs `Ka > Kp`. With R&Q's dynamic parameters at small `dt` the inertia term `M/dt^2` swamps `Kp` and hides it — so a test that fails to show oscillation may just be in the wrong regime, not fixed.

**2. What crosses between EP and activation (`transfer_plan.py`, `interpolation.py`, `averaging.py`)**

Nothing declares the crossings directly; they are read off three name→index dicts every generated module carries: `missing` (what it needs from the *other* side), `provides` (what its own `missing_values()` hands to the other side) and `parameter`.

- `transfer_plan.resolve(ep_module, activation_module)` is the pure half — no meshes, no function spaces. The controller passes it `ode_modules.ep` and the *backend*: `activation_module` is anything with `missing` and `provides` dicts (the `CrossingSide` protocol), a generated module or a `CoupledBackend`, so `ode_modules.mechanics` is no longer read by the controller, and `resolve(ep, backend)` equals `resolve(ep, backend's module)` for `GeneratedActivation`. It pairs each side's `missing` names against the other side's `provides`, and raises `ValueError` naming every name either side needs that the other does not produce (checked in both directions before raising, so one error reports the whole mismatch) — the guard against mismatched splits or stale generated code. `lmbda` is not read from a `provides` dict — it comes from the fibre stretch of the mechanics solve, not a generated `missing_values()` — so whether it crosses back to EP is a capability question, answered by whether `lmbda` is in the EP module's `parameter` dict; `dLambda` never crosses back (no shipped EP remainder consumes it). The result is a `Crossings(forward, backward, stretch_to_ep)`.
- `transfer_plan.TransferPlan` is the runtime half, built from a `Crossings`, the EP module, beat's `DolfinODESolver`, and a `CoupledBackend`. **Forward** (`.forward(t)`): calls the EP module's own `missing_values()` on beat's current state/parameter arrays and interpolates each row into the backend's `inputs` (a quadrature space, typically, on the other mesh) via `interpolation.TransferOperator`. **Backward** (`.backward()`): **averages, never point-interpolates** — λ and everything else crossing back are discontinuous across mechanics cells, so point interpolation into a continuous P1 space would take each node's value from whichever neighbouring cell was visited last. It averages each backend output onto a space on the mechanics mesh matching the EP ODE space (`averaging.make_averager`: lumped nodal average for a P1 target, exact cell average for DG0), interpolates *that* onto the EP ODE space, and writes the result **in place** into `ode.missing_variables` / `ode.parameters` — beat's `DolfinODESolver` holds those arrays by reference at construction, so rebinding them would leave EP integrating with stale data. Because of that, the EP ODE space must be P1 or DG0 (`NotImplementedError` otherwise — averaging is only defined onto those two), and whenever `lmbda` crosses back, `ode.parameters` must already be 2-D (one column per point): a λ that varies between points cannot land in a parameter array with one value for all of them.
- `interpolation.TransferOperator` is unchanged in mechanism (`dolfinx.fem.create_interpolation_data` / `interpolate_nonmatching`, precomputed once at construction) but now refuses a quadrature-space *source* with `ValueError` rather than letting dolfinx abort the whole process — quadrature values only exist at that element's own points and cannot be interpolated from.

**3. Mechanics problem and drivers (`mechanics.py`)**

There is no problem subclass: stock `pulse.StaticProblem` is used, unmodified, or stock `pulse.DynamicProblem` when a heart beat needs inertia, damping, cavities or a circulation, with `GeneratedActivation`, `ZetaSplitUFL` or `CrossbridgeSegregated` as `model.active`. The active stress comes from the backend's `S`. Solver options belong to whoever builds the problem, not to any backend, driver or the controller. The tests, `strong_coupling_zetasplit` and `circulation_biv` set `snes_atol = 1e-9`, tightened from pulse's default `1e-6`: at resting calcium the first residual is already ~1e-9–1e-8 and stalls at round-off, which a pure relative tolerance cannot converge, so the line search reports failure although the state is converged. A cavity row in m³ is a second reason, since `1e-6` would allow a volume error of up to a millilitre. `rodero_05` copies physcardems' options instead, and so runs at pulse's default `snes_atol` 1e-6. The m³ argument does not apply to it: its cavities are controlled, and pulse scales a controlled cavity's rows to mL (volume) and kPa (pressure). `DynamicProblem.parameters["dt"]` is a pint `Variable` in seconds, compiled into the form, so changing it means rebuilding the problem, and nothing in simcardemsx sets it. The controller refuses a mismatch instead (§5). `solve()` first copies the current states (`u`, cavity pressures, circuit states) into their `_old` copies, and `DynamicProblem` advances `v_old`/`a_old` only after convergence, so `problem.reset_states()` restores a failed step exactly, which `pulse.cycle`'s rollback relies on.

The controller never calls `problem.solve()` itself. It calls `advance(t_n, dt)`, both in ms, on a **mechanics driver**. `MechanicsDriver` is a runtime-checkable protocol with two members. `problem` is always the underlying `pulse.StaticProblem`/`DynamicProblem`, never the driver itself; the controller's guards read it, and so does the Newton iteration count. `advance` returns whether the step converged. `as_driver` wraps a `pulse.StaticProblem` (or `DynamicProblem`) in `Solve`, whose `advance` is just `problem.solve()`, so passing a problem behaves as it did before drivers existed. It checks that type first: a problem already has a `problem` attribute (its `NonlinearProblem`), so the protocol check alone would take one that ever gained an `advance` for a driver. Anything else with both members is returned unchanged, and anything without them raises `TypeError`. The two other drivers are where their unit conversions live. The controller's clock is ms throughout, and apart from the drivers only its `DynamicProblem` `dt` guard converts:

- `CirculationClock(problem, time_unit="s", beat_phase=None, period=None)` drives a closed-loop circuit (§4). pulse gives the circuit a clock of its own, in the `.ode` file's time unit: `problem.circulation_time` and `problem.circulation_dt`, constants the caller sets. `advance` sets them to `t_{n+1}` (the circuit's right-hand side is evaluated at the end of the step) and to `dt`, and sets `beat_phase` to `t_{n+1} mod period`. All three are converted to `time_unit` (`"s"` for Regazzoni's circuit, or `"ms"`), and then it solves. `beat_phase` exists because UFL has no `Mod`: Regazzoni's circuit with its `timing` component dropped takes the phase as an input. It must be *the very* `Constant` in `problem.circulation_missing`, because pulse compiled the circuit's form against those objects: any other Constant, even an equal one, is never read, and the phase stays frozen. The constructor therefore checks identity (`is`). It raises `ValueError` for that, for a problem with no circulation, for an unknown `time_unit`, or when only one of `beat_phase`/`period` is given. `period` (ms) must match the circuit's own `RR = 1/HR`. HR must go into the *nested* parameters before `regazzoni2020.flat_ode_parameters` flattens them, since flattening derives `RR` and the chambers' activation offsets from it. Overriding the flat `HR` afterwards does not move them; at 1 Hz it leaves `RR` at the default 0.8 s against a 1 s phase.
- `Cycle(controller)` steps a `pulse.cycle.CycleController` (§4). `advance(t_n, dt)` is `controller.step((t_n + dt)·1e-3, dt·1e-3)`, since `pulse.cycle` is SI throughout. A `dt` left in ms still converges, and steps the Windkessel by 2 s; nothing else would catch that, so `test_cycle_steps_pulse_in_seconds` pins the conversion. `controller.initialize(t0)` is the caller's, once, before the first `advance`, with `t0` in s: the `SimulationController`'s start time (always 0), converted. `step` raises `RuntimeError` if it has not been called. Rollback and retry happen *inside* `advance`. After a failed solve, `problem.reset_states()` runs and the solve is retried once with a fresh preconditioner. If the retry fails too, it rolls back again and returns `False`, with the phases and records untouched. The controller's `RuntimeError` therefore leaves the mechanics at the last converged state and the backend unaccepted.

`backend.post_solve()` — called by the caller after each converged solve — does what used to be `MechanicsProblem.post_solve`: for `GeneratedActivation`, storing the states/λ/outputs of the step the converged residual used as the new "previous" values, evaluated before anything is overwritten; for `ZetaSplitUFL`, recomputing `lmbda`/`dLambda`/`Ta` from the solved displacement and advancing the Land state.

**4. Circulation: closed loop and open loop**

A beat needs its cavities closed by something. pulse offers two ways, and each is driven through the controller by its own driver:

- **Closed loop (Stage A, `CirculationClock`).** `pulse.circulation.GotranxCirculation` solves Regazzoni's 0D circuit (`circulation.regazzoni2020.ODE_FILE`, circulation 0.4.0) in the same Newton system as the displacement. A coupled cavity is a `Cavity(marker, volume=None)` with a `ChamberCoupling(marker, "V_LV", "p_LV")`. pulse points its volume at the chamber's volume state, and the cavity pressure is the constraint's Lagrange multiplier. Blood therefore goes round the loop, the total volume is conserved, and each beat starts from wherever the last one left the circuit. The chambers the 3D mesh replaces are dropped from the circuit (`drop_components=("timing", "LV")`, or `("timing", "LV", "RV")` for a BiV). The remaining 0D chambers activate on `beat_phase`. The circuit works in mL, mmHg and s, pulse in SI. The coupling rows and their Jacobian blocks belong to pulse and are tested there (`tests/test_circulation_coupling.py`), not here.
- **Open loop (Stage B, `Cycle`).** `pulse.problem.CavityControl` (pulse ≥ 0.10) gives a *controlled cavity* one pressure unknown whose equation `Constant`s switch at run time, without rebuilding the form. In volume mode it is `V(u) = V_target`. In pressure mode it is `p = A + B·V(u)`, where `B = 0` prescribes the pressure and `B ≠ 0` ties it to the volume inside Newton, as a Windkessel does during ejection. `pulse.cycle.CycleController` is the policy on top, a port of physcardems' cycle controller. It steps each controlled cavity through the five **cycle phases**: PRELOAD (a pressure ramp), ISOVOLUMIC_CONTRACTION (volume held at EDV), EJECTION (an implicit three-element Windkessel, affine in V), ISOVOLUMIC_RELAXATION (volume held at ESV) and FILLING (a prescribed inflow rate). Transitions are decided on Python floats between converged steps. Each cavity has its own SI `CycleParams` and Windkessel, and nothing connects them: ejected blood leaves the model, and filling is prescribed. The pitfalls:
  - `CavityControl`'s values are SI (m³, Pa, Pa/m³), so a controlled cavity requires `mesh_unit == "m"`, and `StaticProblem` raises `ValueError` otherwise.
  - A `Cavity` takes exactly one of a `volume`, a `control` or a chamber coupling, and `ValueError` names the marker otherwise.
  - `CycleController.records[marker].phase` is the phase for the *next* step, not the one its `V`/`P` were solved under, so label a step by the phase read *before* `advance`. `test_cycle_coupling.py` and `rodero_05`'s `log.csv` both do.
  - `preconditioner_lag` is set through the PETSc options database, since petsc4py has no setter. It is 1 on the first solve, after each phase switch and on a retry.
- **The multiplier is the wall pressure only for a closed cavity surface.** Every cavity term pulse builds (plain, coupled or controlled) is the variation of the divergence-theorem volume `V(u)`. That equals the pressure traction `p∫δu·n da` only when the cavity surface is closed, or when its open rim lies in a plane through the origin and does not move out of it (an LV endocardium whose base is fixed in the normal direction). Otherwise the load is not a pressure, even though the solve converges and the number looks like one. `rodero_05` has no base BC, so its valve plugs, which close the LV and RV cavities, matter for more than stiffness. `test_rodero_case.py` checks the closure by shifting the mesh, since a closed surface's volume does not depend on the origin: it asserts that the LV and RV volumes do not change. For contrast, a one-off probe made when the example was written found that the open EPI and BASE surfaces change by 9% and 16% under the same shift; no test asserts that.

**5. Orchestration (`controller.py`)**

`SimulationController(mechanics, ep_solver, backend, ode_modules, dt_mech, dt_ep)` takes a mechanics driver or a bare problem, which `as_driver` wraps in `Solve`; the keyword was `mechanics_problem` before drivers. `step()` is the whole time-stepping algorithm, and it drives any `CoupledBackend` (`GeneratedActivation`, `CrossbridgeSegregated`) — `ZetaSplitUFL` remains usable directly against `pulse` without it. In order: take a `snapshot()` of every component (§7); run `dt_mech / dt_ep` EP micro-steps (`ep_callback(t, ep_step_idx)` after each); `TransferPlan.forward(t)` at the new `t`, into the backend's `inputs`; call `backend.begin_step(t_n, dt_mech)` with the *old* `t` (for `GeneratedActivation` that sets `backend.t` and `backend.dt`; for `CrossbridgeSegregated` it advances the trial), and then `mechanics.advance(t_n, dt_mech)`, which is one Newton solve for `Solve` and whatever the driver does otherwise; `backend.post_solve()`; `TransferPlan.backward()`; the step counter; `mech_callback(t, mech_step_idx, newton_iterations)`. **A failed step is rolled back.** If anything before `mech_callback` raises (any `BaseException`, `KeyboardInterrupt` included), or `advance` returns `False`, `step` restores the snapshot and raises: the error itself, unchanged, or `RuntimeError` for `advance`'s `False`. Everything is then bit-identical to before the step, under every driver: EP's states (its micro-steps undone), EP's `missing_variables`/`parameters`, `u`, the cavity pressures and circuit states, the cycle, and the backend, whose pending trial is discarded. `controller.t` is `t_n` again, and `controller.t_failed` is where the step would have ended, `t_n + ep_steps_per_mech·dt_ep`, the EP loop's own arithmetic, which `t_n + dt_mech` can differ from in the last bit. `t_failed` is reset to `None` at the start of every step, and stays `None` if the restore itself raised; that error is then raised with the step's as its cause. A caller can therefore retry the step, and on pulse's default solver the retry reproduces the uninterrupted run bit for bit (gate R2). `mech_callback` is outside the rollback, since the step is accepted by then: an error from it leaves `t` at `t_{n+1}` and `t_failed` `None`. What `ep_callback` wrote during the micro-steps (a demo's EP saves) is not undone. `Cycle` still rolls back and retries its own solve inside `advance`. `newton_iterations` is read from `mechanics.problem.problem.solver`, i.e. the last solve's, which after a `Cycle` retry is the retry's. Construction guards that `backend is mechanics.problem.model.active` (`ValueError` otherwise — the controller steps the backend and the problem solves with its own, so they must be the same object), that `dt_mech` is a whole multiple of `dt_ep` (rtol `1e-9` — round-off, not a real remainder), that a `pulse.DynamicProblem`'s `parameters["dt"]` (s) equals `dt_mech` (ms), to the same rtol (`ValueError` otherwise — the inertia term is assembled against the problem's own `dt`, so the two clocks would silently drift apart), and, when the backend stores states on a quadrature space, that its `quadrature_degree` equals the `quadrature_degree` in `geometry.dx.metadata()` (the measure every integral of the pulse form uses) — otherwise FFCx would ignore the form's `metadata["quadrature_degree"]` and silently evaluate the whole momentum integral (passive + active + compressibility stress) at the states' own quadrature degree instead — and that `ep_solver.ode` is a `beat.odesolver.DolfinODESolver` (`TypeError` otherwise: the transfer plan writes into its `missing_variables`/`parameters` arrays, which beat's other ODE solvers do not have in that form). `TransferPlan` construction (`resolve` plus the spaces/operators) happens once, in `__init__`.

**6. Output and the examples**

`datacollector.py`'s `DataCollector` + `Timers` write point/field EP and mechanics data (via dolfinx's function evaluation at points) and simulation timing, driven by callbacks passed into `SimulationController.step`. `DataCollector` is **deprecated** (`DeprecationWarning` at construction) and no example uses it: the examples write `results.bp` and `log.csv` during the run (§7), and their `post.py` replots from them.

`numerical_experiments/strong_coupling_zetasplit/main.py` is a full worked example wiring all of the above together end-to-end (mesh generation via `cardiac-geometriesx`, `beat` conductivities/stimulus/solver setup, `pulse` material/BCs, the controller loop, and its output, checkpoints and restart, §7) — read it to see how the pieces connect in practice rather than inferring it from the library modules alone. `--odefile` selects which `.ode` file (and hence which split) runs; output goes to `output/<odefile stem>/`; the EP ODE space is P1; and it writes `timings.json` (`ep_ode_s`, `ep_pde_s`, `mech_s`, `setup_s`, `loop_s`, `total_s`, and `newton_its`, the Newton iterations of the whole run; after a restart, of that process only) — the wall-time baseline the ODE-performance sub-project (`.scratch/roadmap.md`, sub-project 7) will compare against. Its slab fibres are `DG_1`. They were checked once by hand, not by a test, when commit 1b57688 was made: at the degree-4 quadrature points the forms read them at, they are unit length to round-off (max |1 − |f0|| = 2.2e-16; see the `lv_ellipsoid` testing note for why that is where to check). Its model is `model_settings()`, plain values the run reads (the EP time step, the slab, EP's space, conductivities, chi, C_m and stimulus, and the mechanics' spaces, compressibility, material in Pa and BCs), which `config.resolved.toml` and the physics hash (§7) take; `default_config()` is gone. The mesh is generated on first use into `meshes/slab_dx<dx>/` beside `main.py`, so `post.py` finds it from any directory, and a cached mesh of another slab (by its `info.json`) is refused with `ValueError`. `log.csv` has `t_ms`, `newton_iterations`, and `lmbda_mean` and `Ta_mean_kPa`, the means at the form's quadrature points. `post.py` writes `fields.bp`, `traces.csv` (`v`, λ and `Ta` at a corner point and as volume means), `DataCollector`'s four plots and `log.png`.

The slab example takes `--scheme {monolithic,segregated,stabilized}` (default `monolithic`), `--dt-mech` (ms, a whole multiple of the 0.05 ms EP step), `--t-end` (ms), `--output-dir` (default `output/<odefile stem>`) and `--snapshot-every` (ms, default off), `--crossbridge {Land2017,RDQ18,RDQ20MF,Lewalle2024}` and `--sl-ref` (µm), and the output and restart options every example shares (§7). `--crossbridge` runs `CrossbridgeSegregated` of that model in place of `GeneratedActivation`, at the form's `QUAD_DEGREE`, and needs the Ca_i `.ode`: with the zeta split, `resolve()` raises `ValueError` naming `Zetas` and `Zetaw`. `--scheme stabilized` and `segregated` map onto `stabilized=True`/`False`, and `--scheme monolithic`, the default, is refused at the start with a message, since the model is NumPy and cannot be re-integrated inside Newton: pass `--scheme stabilized` or `segregated`. `--sl-ref` sets `SL_ref`, which RDQ18 requires. `run.json` records `backend` as `generated` or `crossbridge:<model>`, and `results.bp`'s `lmbda` is `outputs["lmbda"]`, which both backends carry. Smoke runs (Ca_i split, stabilized, dt 1 ms, 20 ms) all reach `t_end`: final mean `Ta` Land2017 1.2e-3, Lewalle2024 5.8e-6, RDQ18 (`--sl-ref 2.0`) 0.138 and RDQ20MF 0.355 kPa (with the sub-stepping fix that crossbridge 0.3.3 released). `tests/test_slab_example.py` runs the example as a subprocess from its own directory (testing notes). `circulation_biv` takes `--scheme`, `--dt-mech` and `--snapshot-every`. Both leave a `Recorder`'s `steps.csv` and `run.json`, and with snapshots `snapshots.npz`, beside their own output.

`numerical_experiments/scheme_comparison/` compares the three schemes on the same runs. `record.py` holds `Recorder`, called after each `backend.post_solve()` and once more at the end, whether or not the run completed; it is serial only. It records the git commit, and whether a tracked file differs from it (`git_dirty`), when the run starts, through `simcardemsx.provenance`. It is also a checkpoint component (namespace `recorder`, no Functions, §7): its rows and snapshots go into a sidecar, `restart_recorder_<t>.npz`, with every checkpoint, and the newest two are kept, since `restart.json` names the older one until the newer is complete. It is written atomically, into `.restart_recorder_tmp_<pid>.npz` (which the `restart_recorder_*.npz` glob does not match) and then `os.replace`d, because an end checkpoint on a periodic one's time rewrites the very file `restart.json` names. A restarted slab or BiV run therefore gives the same `steps.csv` and `snapshots.npz`. `--snapshot-every` is not physics, so a restart may change it; `snapshots.npz` then mixes the two cadences, or, if the restart turns snapshots off, keeps the first leg's file as it was. Both examples end through `demo_io.finish` (§7), i.e. `finish_after_artifacts`, which writes their own files first, each guarded so that a failure cannot stop `run.json` or replace the loop's exception, and `run.json` last, with its `extra=` keys (`provenance`, `history`, `restart`) merged in. The recorded `failure` is `failure_of(e)`, the exception and every one behind it: petsc4py re-raises a `KeyboardInterrupt` from inside a solve as `PETSc.Error(101)`, with the interrupt as its cause. `metrics.py` holds the pure functions (numpy/scipy only) and `report.py` reads a directory of runs laid out as `<root>/<geometry>/<group>/<scheme>/dt<dt>/` into `report.md` and figures, where a missing run shows as "—" and never stops it. Within a group every error and order is taken over one grid, the multiples of the group's coarsest dt: the volume-mean differences (λ and `Ta`) from `steps.csv` at every step on it, the RMS of the fields from the snapshots on it. A reference is always a monolithic run that reached `t_end` (or, on the BiV, the Richardson extrapolation of the two finest such runs, against which no orders are given). `element.py` is the one-element study (`static-caisplit`, `static-zetasplit`, `dynamic-zetasplit`: gates 1, 4 and D2's regimes, each under every scheme and dt against a monolithic reference at a smaller dt). Its builders and inputs are copies of `tests/conftest.py`'s and `test_dynamic_coupling.py`'s, by value, so keep them in step with the gates. `run.py --study {slab,biv}` runs the slab (zeta and Ca_i splits) or BiV matrix, one subprocess per run, into `<root>/<geometry>/<split>/<scheme>/dt<dt>/`, with `--overwrite`: a run is redone from scratch, and the folder rules (§7) would refuse an interrupted run's folder. A run is done once it has a `run.json` that parses and names no `KeyboardInterrupt` or `SystemExit` in its `failure`, so a re-run skips finished runs and redoes interrupted ones. A failed run is done, since its failure is a result, and the naive scheme's non-zero return does not stop the batch. `tests/test_scheme_comparison.py` covers `metrics`, `Recorder` (with `finish_after_artifacts` and its `extra`, `failure_of`, the git provenance, and a restart through the sidecar, with and without snapshots, giving the same files), and `run.py`'s `MATRIX`, `pending_runs` and `--overwrite`. `tests/test_scheme_report.py` covers `report.py` on fabricated runs in the real file formats, each quantity `X* + k·C·dt`, so every error, order and extrapolation has a known value: orders of 1, the exact Richardson reference, the choice of ε, the common grid, a failed monolithic run never being the reference, and the load problems.

`numerical_experiments/circulation_biv/main.py` is the closed loop (Stage A) end to end. It is pulse's `demo/time_dependent/monolithic_3d0d_biv.py` with the prescribed Bestel tension replaced by the zeta split's `GeneratedActivation`, driven by beat EP on the same mesh.

- **Set-up.** It builds the UKB atlas mean BiV at end diastole, clipped at the valve plane, in metres, with LDRB fibres on `Quadrature_6`. The geometry, the fibres and the backend's states are all at quadrature degree 6, because they must agree. Regazzoni's circuit runs alone to a limit cycle from the mesh's volumes, which gives the end-diastolic pressures. The mesh is prestressed to recover the unloaded reference, then inflated back to EDV under volume control.
- **The run.** The coupled `DynamicProblem` is closed by the circuit (`drop_components=("timing", "LV", "RV")`) and clocked by `CirculationClock` at 1 Hz, with `dt_mech` 2 ms and `dt_ep` 0.05 ms. EP is on P1, and ToR-ORd's own stimulus fires everywhere at `t = 0`.
- **Options and output.** `--t-end` is in ms (default 1000, one beat), `--tref` is below, and `--outdir` (not `--output-dir`, which its `post.py` takes) defaults to `numerical_experiments/circulation_biv/output/`. Besides the shared options and files (§7) it writes `pv_loops.png` and `summary.json`, drawn from `log.csv`'s rows, so after a restart they cover the whole run; `log.csv`'s columns are listed in the module docstring. `summarise` and `plot` live in `post.py`, which `main.py` imports, and `post.py` writes `summary.json` and `pv_loops.png` again, `fields.bp`, and `stats.csv` (λ and `Ta`: mean, min and max over the quadrature points). `summary.json` reports each ventricle's `V_range_mL` and `V_range_fraction`, the range of `V` over the run, not a stroke volume and an ejection fraction: the beat is not periodic, and `V` also changes while the outflow valve is shut. The volume actually ejected is each open interval's `ejected_mL`. It is serial only, since it reads the cavity pressures and circuit states as `x.array[0]`.
- **Caches.** The mesh, the circuit's operating point and the prestress are cached under `meshes/ukb_mean_ed_clipped/`, keyed only by whether they exist, so delete that directory after changing the mesh size or the period. The physics hash includes those settings, but a change to them is hashed, not applied, until the cache is gone. `post.py` reads the cache and never regenerates it; a missing cache exits with the reason.
- **Restart.** A restart still builds the problem and reads the circuit's operating point and the prestress from the cache, but skips the inflation, the initial state, `reset_stretch()` and `plan.backward()`, which the checkpoint replaces.
- **Installs.** Generating the mesh needs `ukb-atlas`, `fenicsx-ldrb` and pyvista, installed by hand as the module docstring says. `fenicsx-ldrb` pulls in numba, which requires numpy < 2.5, so installing it downgrades a newer numpy, and putting that numpy back leaves numba unimportable. Both are also in the `demo` extra, so `pip install -e .[all]` (which `.devcontainer/setup.sh` runs) pulls them in too.
- **`Tref`.** `--tref` scales Land's `Tref` (the `.ode`'s 120 kPa) and defaults to 3, physcardems' eLife calibration (`LAND_SCALES`); `summary.json` records it as `tref_scale`. At the `.ode`'s own `Tref` (`--tref 1`) the LV's isovolumic peak stays about 2 mmHg below aortic pressure, so its aortic valve does not open in the first beat, while the RV ejects. Stage A's acceptance is taken at the default.

`numerical_experiments/rodero_05/` is the open loop (Stage B) end to end: physcardems' `em_tref7` run of its `rodero_05` case (`cases/rodero_05/run_rodero_em_tref7.py` with `configs/elife/em_tref7.toml`) on simcardemsx and pulse. `case.py` loads physcardems' case directory in place, and each parameter is copied as a number with the file and line it comes from. It raises `FileNotFoundError` listing every missing file before io4dolfinx is reached. `main.py` wires and runs the case.

- **The case.** It is a coarse Rodero BiV (24 811 cells) whose valve plugs (cell tags 7–10) close both cavities. It is shrunk ×0.9 about its centroid, physcardems' stand-in for unloading, and has DG0 fibres, a per-node LAT and a per-node ToR-ORd cell type.
- **What it exercises from sub-project 6.**
  - EP parameters and initial states per P1 dof: each node gets its cell type's steady state, its cell type, and `i_Stim_Start` equal to its LAT. ToR-ORd's own stimulus therefore activates the tissue, and there is no PDE stimulus.
  - `Ta` masked out of the plugs, through `tension_scale`.
  - Spatially varying passive stiffness: Holzapfel-Ogden's four moduli are DG0 fields, ×3 in the plugs. This is the same stress as physcardems' `ScaledModel`, since the stress is linear in the moduli.
- **Mechanics.** `DynamicProblem` with dt 2 ms, `Compressible2`, `Viscous`, an epicardial spring and damper, and nothing on the base. Both cavities are controlled by one `CycleController` through `Cycle`, with physcardems' solver options (GMRES, LU lagged by 20, persistent). Each Land parameter goes to every half of the split that declares it (`place_land`). The run starts with an accepted solve at rest and zero cavity pressure, then calls `cycle.initialize(0.0)`.
- **Options.** `--case-dir` defaults to `third-party/physcardems/cases/rodero_05`. `--tref` is the `Tref` scale on 120 kPa (default 7, em_tref7). `--t-end` is in ms (default 800, one beat; `--t-end 20` is the smoke test), and `--output-dir` defaults to `numerical_experiments/rodero_05/output/`. The shared options and files are in §7. It also checkpoints after every step at which a cavity's phase switched, as physcardems does. The physics hold the case directory by its resolved path and the sha256 of every file the run reads from it, so a case edited in place, or moved, is other physics.
- **Output.** It writes `pv_loops.png` and `summary.json` (with the Stage B criteria). `log.csv` is appended every step and has `next_phase_LV/RV` (the phase after the step, physcardems' `phase` column), `first_iterations` and `first_reason` beside the last solve's, so the summary is computed from `log.csv` alone, after a restart over the whole run. The criteria include `reached_t_end`, and the run records any exception, `KeyboardInterrupt` included, in `failure` before re-raising, so `newton_converged_every_step` is never true for a run that stopped early. A step whose retry converged counts as converged, and the retries are reported under `newton`. It has no `Recorder`, and writes its own `run.json` (with `t_fail_ms`) once set-up is done, with `status: running`, and again last of all at the end; `post.py` treats a `run.json` still at `running` as a run that did not finish. It is serial only, and the 800 ms run takes hours.
- **Restart.** A restart skips the unloaded solve and `cycle.initialize`, which the checkpoint replaces (`Cycle(cycle)` is passed unwrapped, so the checkpoint holds the cycle). Its lagged LU cannot be saved (§7), so a restart agrees with the uninterrupted run only within the solver tolerances: about 1e-7 relative at 20 ms after a restart at 10 ms. Apart from that, **the run is not bit-reproducible across processes even without a restart**: two processes of the same code, `PYTHONHASHSEED` and generated code, single-threaded BLAS and OpenMP, differ at round-off from the unloaded solve on. The cause is not found; the lagged GMRES/LU and the larger mesh are the suspects, since the BiV (pulse's default solver) is bit-reproducible. Compare `rodero_05` runs to round-off, never bit for bit.
- **`post.py`.** Besides `summary.json`, `pv_loops.png` and `fields.bp`, it writes `active_stats.csv`, physcardems' minus `frac_h_zero`: `Ta` percentiles over the myocardium, and per ToR-ORd cell type the median `Ta` and λ. A quadrature point's cell type is the argmax of the three P1 indicator functions interpolated there, not the rounded interpolated type number, which between endo (0) and mid (2) nodes passes through epi (1). It also writes the pseudo-ECG (`ecg.csv`, `ecg.png`, one row per saved `v`): `beat.ECGRecovery(v, sigma_b=1, C_m=1, M=1)`, which with `M` the identity is physcardems' G = I convention (a scaled potential, not a physical one), at the case's electrodes (`case.electrodes`, converted from cm to m), as `beat.ecg.Leads12`.
- **Differences from physcardems.** The module docstring lists the known differences, kept on purpose. Read it before comparing numbers.

`config.py` defines pydantic models (using `pydantic_pint` for unit-aware fields) for simulation configuration; most of it beyond `Conductivity` is currently commented out / unimplemented.

**7. Checkpoint, rollback and results (`checkpoint.py`, `results.py`, `provenance.py`)**

Any run driven by `SimulationController` can write a checkpoint between steps and continue from it in a fresh process, as the same run (gate R1), and a failed step is undone in memory (§5, gate R2). The file layout and rules are those of the pulse 0.11 and beat 0.7.1 `run`/`post` CLIs, so that a later `simcardemsx` CLI is a loop around the same calls. What a beat, pulse or crossbridge object must save is listed by that library's own API (beat's and pulse's `restart_functions`/`restart_metadata`, pulse's `CycleController.state_dict`, crossbridge's `get_state`/`set_state`), not by simcardemsx, so a change there is made upstream.

- **`Checkpointable`** is a runtime-checkable protocol: `namespace`, `restart_functions()` (`(name, Function)` pairs holding the state, possibly the component's live Functions), `restart_metadata()` (the rest, JSON-able: plain Python types, no numpy scalars) and `load_restart(functions, metadata)`. `load_restart` always receives a *fresh* `restart_functions()` list whose values the caller has already overwritten, and raises `ValueError` if the metadata is of another kind of object. A component may also define `write_sidecar(folder, t_ms)`/`read_sidecar(folder, t_ms)` for files of its own, which the checkpointer calls if present. Function names must be unique across all components saved together: simcardemsx's are prefixed (`activation_*`, `transfer_*`), pulse's are `mechanics_*`, and EP's are beat's own, `v` and `state_<name>`, unprefixed.
- **The components.** `controller.components()` lists, in restore order: `EPState` (beat's `v` and `state_<name>`; its metadata holds the state names and beat's `restart_metadata()`, the time step the PDE matrix was assembled at, since beat reuses the matrix while dt stays within 1e-12 and a reassembly at a dt differing in its last bit would move EP at round-off); the `TransferPlan`; `MechanicsState` (pulse's own `mechanics_*` Functions: `u`, `p` if incompressible, the cavity pressures, the rigid-body `r` and the circuit states, each with its `_old` copy and a circuit state also with its BDF2 `_prev`, and `DynamicProblem`'s `v_old`/`a_old`; in the metadata, the circuit's step count, which selects its stencil); `CycleState` (`CycleController.state_dict()`, in SI, no Functions); the backend; and the controller itself (namespace `simcardemsx`: `t_ms`, both step counters and both dt, and its `load_restart` refuses another `dt_mech` or `dt_ep`). `CycleState` is included only when the driver *is* a `Cycle` (an `isinstance` check): a `Cycle` wrapped in another driver is silently left out of every snapshot and checkpoint, so pass `Cycle(cycle)` itself, as `rodero_05` does.
- **The backends.** Both are `Checkpointable` with namespace `activation`, and both re-average `active_tension` on load instead of saving it. `GeneratedActivation` saves `states_prev`, `lmbda_prev`, the frozen `lmbda`/`dLambda`, `tension_kPa`, `stiffness_kPa` and its outputs, and refuses another backend or scheme. `CrossbridgeSegregated` saves `lmbda_prev`, λ_{n−1}, `tension_kPa`, `stiffness_kPa`, `J_TRPN` and each array of the model's `get_state()` (`activation_model_<key>`, cells on the last axis, blocked onto the backend's element), with the model's scalars in the metadata. It refuses another backend, model or `stabilized`, and its `load_restart` discards a pending trial. Neither checks the configuration (`Tref`, `SL_ref`, the split): that is the physics hash's job. Both have `step_pending`, which is not part of `CoupledBackend`: `True` between `CrossbridgeSegregated`'s `begin_step` and `post_solve`, and always `False` for `GeneratedActivation`, whose `begin_step` only sets `t` and `dt`.
- **No restore calls `plan.backward()`.** The `TransferPlan` (namespace `transfer`) saves the rows of EP's `missing_variables`/`parameters` that `backward()` writes, as Functions on the EP ODE space (`transfer_missing_<name>`, `transfer_parameter_lmbda`), and copies them back in place. Moving the backend's outputs back instead would be wrong before the backend's first `post_solve`, when they are zero: a rollback of the first step or a checkpoint at t = 0 would write λ = 0 into EP, which holds λ = 1.
- **`Snapshot`.** `take_snapshot(components)` copies every component's Function values and deep-copies its metadata; `restore_snapshot` writes them back through `load_restart`, after refusing (`ValueError`, before writing anything) other namespaces, names or array sizes. A snapshot is copied back by position, so the names must also be in the same order, which they are, since a snapshot never leaves its process. `controller.snapshot()`/`controller.restore(snapshot)` do this for `components()`, and the rollback (§5) takes one per step.
- **`Checkpointer(controller, folder, *, physics, extra=())`.** Its components are `controller.components()` followed by `extra` (the slab and BiV pass their `Recorder`). It refuses shared namespaces or function names, and metadata that uses its reserved keys (`physics_hash`, `functions`, `provenance`, `history`).
  - **`write()`** checkpoints at `controller.t`: every Function into `restart.bp` (io4dolfinx's `write_function_on_input_mesh`, so in input-mesh order, unaffected by nightly's cell reordering), then each sidecar, then `restart.json` last and atomically (`write_json`: a temporary file and `os.replace`, on rank 0), so `restart.json` only ever names a complete checkpoint. It raises `RuntimeError` while the backend has a step pending: checkpoint between steps. `restart.json` has one entry per namespace, times in ms except the cycle's (SI, as pulse writes it). The `simcardemsx` entry adds the physics hash, each namespace's function names, this process's provenance and `history`, the provenance of every process that wrote or resumed the run.
  - **`restore()`** returns the checkpoint's `t` (ms). It checks the physics hash (`check_restart`: `FileNotFoundError` without `restart.json`; `ValueError` for another hash, or for a `restart.json` that has none), the function names of each namespace as a set, and that `restart.bp` holds `t` for every function, all before reading anything, and each `ValueError` names what differs. A refused restore changes nothing: anything raised once the reads have begun (a read, a component's `load_restart` refusing its metadata, a `read_sidecar`) is raised only after every component has been put back from a snapshot taken before the first read.
  - **Names, not positions.** Each Function is read by its name, and `EPState` and `GeneratedActivation` accept their state names in another order (`GeneratedActivation` permutes `states_prev`'s components into its own) while refusing another set. gotranx 1.8.0 orders a generated module's states by `PYTHONHASHSEED`, so another process may list them differently; a strict xfail tracks it, and the fix belongs in gotranx. A new component whose Functions or metadata hold positions must record the names and map them on load.
  - **No duplicate timestamps.** io4dolfinx appends a Function written at a time the file already holds, and reads back the first. So `write()` writes no Functions at a time it knows `restart.bp` holds completely and only rewrites `restart.json` and the sidecars. It knows the times it wrote and those its `restore()` found, so a fresh checkpointer assumes `folder` holds no `restart.bp` of another run, which `prepare_output` ensures.
  - **A checkpoint killed partway** (after some or all of its Functions, before `restart.json`) is not restored from, since `restart.json` still names the one before it, and the restarted run does not complete it either. Every time `restart.bp` holds, for any Function, later than the checkpoint `restore()` restored is *foreign*, and `write()` at a foreign time writes nothing (no Functions, no sidecars, no `restart.json`) and logs a warning. Rewriting only `restart.json` there would pair the killed process's Functions with the new run's metadata, and writing the Functions again would append duplicates that io4dolfinx never reads back; in a run that is not bit-reproducible (`rodero_05`'s lagged LU) either mixes two runs' states. The restart point therefore stays the checkpoint before it until the next time that is not foreign, which is written as usual. A time this process wrote completely is not foreign, so writing there again still only rewrites `restart.json` and the sidecars.
  - **The physics hash.** `physics_hash(physics)` is the sha256 of the dict as JSON with sorted keys. The dict must hold everything that defines the physics and nothing about the run length, the output or the solver options: a restart may change `--t-end`, the output options and the solver options, and nothing else. Only the hash is stored, so a refusal cannot say which setting differs; `config.resolved.toml` holds the settings for comparing by hand.
- **State that cannot be saved: a lagged, persistent preconditioner** (`snes_lag_preconditioner` with `snes_lag_preconditioner_persists`). Its factorization was computed at an earlier step, and a restarted run factorizes afresh, so the restart agrees with the uninterrupted run only within the KSP and SNES tolerances (`rodero_05`, §6). Under pulse's default solver, a fresh MUMPS LU at every Newton iteration, as in the tests, the slab and the BiV, a restart is bit for bit.
- **`results.py`.** `ARTIFACTS` is the CLIs' folder layout: `config.resolved.toml`, `run.json`, `results.bp`, `log.csv`, `restart.bp`, `restart.json`, `timings.json`, `post/`.
  - `ResultsWriter.write(t_ms, functions)` writes named Functions into `results.bp` (input-mesh order) and never writes a name at or before its last saved time; `resume(names)` takes those times from the file. `read_results`/`read_result_times` read them back.
  - `CsvLog` writes rows of floats on rank 0, each as `repr(float)`, so they round-trip exactly and an integer column such as `newton_iterations` reads back as `3.0`. Its first column must be `t_ms`, and `resume(t)` keeps the rows up to `t`, atomically, refusing another header.
  - `prepare_output(folder, restart=, overwrite=, physics=, artifacts=)` applies the folder rules. A folder holding any artifact (names or fnmatch globs) is refused unless `overwrite`, which deletes only what `artifacts` match, or `restart`, which needs a checkpoint of the same physics. The two flags exclude each other, and a stale `restart.bp` counts as an artifact, so a fresh run never appends to another run's checkpoint.
  - `stride(every_ms, dt_ms)` refuses an interval that is not a whole number of steps. `write_resolved_settings`/`read_resolved_settings` write and read TOML (read with `tomllib`, or with `toml` on Python 3.10, which has none), which has no null, so a `None` setting is left out.
- **`provenance.py`.** `provenance(cwd, comm)`: the git commit and `git_dirty` (tracked files only, with `--no-optional-locks`), the versions of simcardemsx, dolfinx, pulse, beat, gotranx, crossbridge, io4dolfinx, numpy and petsc4py, the MPI size and the UTC time.
- **The examples (`numerical_experiments/demo_io.py`).** The slab, the BiV and `rodero_05` share it, imported as `demo_io` with `numerical_experiments/` on `sys.path`. On the run side, `prepare_run` makes every refusal (a stride, named by its option; the physics; `prepare_output`) before anything is built or written, and exits through `SystemExit` with the reason. Then `start_or_resume` starts `log.csv` and writes t = 0, or restores the checkpoint and resumes `log.csv` and `results.bp`, and `steps_to_take` counts the steps left. `failure_at` gives `run.json`'s `failure` and `t_fail_ms`, `write_end_checkpoint` the end checkpoint, and `finish` writes the end checkpoint, the example's own files (each guarded) and `run.json` last, through the `Recorder` or a `write_run` callable. On the post side are `result_functions`, `write_p1_fields`, `Panel`/`figure`/`plots_available` and `cell_containing`.
  - **Options.** `--save-every` (ms, default `dt_mech`), `--save-every-ep` (ms, default 1, enough for the ECG), `--checkpoint-every` (ms, default 50, physcardems' value), `--restart` and `--overwrite`. Each interval must be a whole number of steps.
  - **Files.** `config.resolved.toml` (every argument and `model_settings()`, rewritten by every run, a restart's too); `results.bp` (EP's `v` and `cai` on P1 every `--save-every-ep`, and `u`, `lmbda`, `tension_kPa` and `stiffness_kPa` every `--save-every`, the last three on the backend's quadrature space, all from t = 0); `log.csv`, one row at t = 0 and one per step, appended as the run goes; `restart.bp` and `restart.json` every `--checkpoint-every` and at the end; `timings.json` (this process's); `run.json`, last.
  - **Folder rules.** A plain run into a folder with results is refused, the default folder included, which may hold results from before these rules.
  - **`physics()`** holds the inputs the run reads: the physics options (`--scheme`, `--dt-mech`, `--tref`, …) and `model_settings()`, with the material as the numbers passed to pulse, in base units, and the library defaults the run uses (pulse's material, beat's stimulus timing, the circuit's parameters, …) read off the library, so a change to those defaults changes the hash. The `.ode` file is in it by name and sha256, not by path. Solver options are not in it, and neither are crossbridge's model parameters (the library's defaults) or pulse's problem defaults that the run leaves unset.
  - **End checkpoint.** Written when the run finishes, or after a rolled-back step, at that step's start. It is skipped while a step is pending, and after a failure that followed an accepted step (in `mech_callback` or a periodic checkpoint), whose log row or `results.bp` fields may be missing: the last periodic checkpoint stays the restart point. A run shorter than `--checkpoint-every` (the slab's default 40 ms, against 50) then has nothing to restart from.
  - A failed step's EP saves, written by `ep_callback`, stay in `results.bp`. A restart from before the step recomputes those times without saving them again, so the values kept are the failed attempt's, which equal the recomputation wherever the run is bit-reproducible.
  - A killed run's fields stay in `results.bp` too. `ResultsWriter.resume` takes each name's last saved time from the file, so the restarted run saves nothing up to it, and the fields between the checkpoint and that time are the killed run's, while `log.csv` is cut back to the checkpoint and rewritten. This is the CLIs' rule. Where the run is bit-reproducible the two agree; where it is not (`rodero_05`), `results.bp` and `log.csv` differ at round-off over that window.
  - A restart whose `--t-end` is at or before the checkpoint takes no step. When it is before, `run.json` says `reached_t_end: false`.
  - **`post.py`**, in each example's directory: `python post.py --output-dir <folder>`. It reads `config.resolved.toml`, `results.bp` and `log.csv` (the BiV's and `rodero_05`'s also `run.json`, if present), rebuilds only the geometry and the spaces the run wrote from (never the coupled problem), and replaces `post/`: the run's own summary and plots by the same functions, `fields.bp` (VTX on P1: quadrature and other discontinuous fields averaged onto P1, continuous ones interpolated), and each example's traces or statistics. Without matplotlib it skips the plots with a warning. Serial only.

## Testing notes

Tests avoid needing a real EP/mechanics stack where possible. The coupling gates for `GeneratedActivation` deliberately do use one, because that is what the claims being tested are about. The static and dynamic gates run on a single element, and the circulation and cycle gates on a coarse LV ellipsoid.

- `test_generated_activation.py` drives `GeneratedActivation` directly (`register`/`post_solve`, no `pulse.StaticProblem`) against the *same* `mechanics` component generated as numpy instead of UFL, as the reference — the isometric-clamp gate matches it to round-off (`rtol=1e-10`). It also holds gate S0, which requires `stiffness_kPa` to equal Land's closed-form `dTa/dλ` of the step (the rate path plus the length path, including the slope of the length dependence on both sides of 0.87) to `rtol=1e-12`, at the point each scheme evaluates it, for all three schemes at dt 2 and 0.05 ms. Further tests pin that `stabilized` is `segregated` plus the `Ka` term: the difference of the two assembled `∫S_ff` must equal `1000·Ka·Δλ/λ` integrated with `stiffness_kPa` as `Ka` (`rtol=1e-12`), which ties the residual's `Ka`, built in `__init__`, to the one S0 checks, built in `register`. They also pin that `tension_scale` masks the term, that `stabilized` refuses the `invariant` formulation, and that `reset_stretch()` makes the schemes agree at rest. The reset is taken after a step that left the frozen schemes a nonzero frozen rate, so it must zero that rate, keep `states_prev` bit for bit, and set `lmbda_prev`, the frozen λ and `outputs["lmbda"]` to λ(u). It also holds gate B1, `tension_scale` on two tets with a DG0 mask of 0 and 1. `S` and `active_tension` must vanish on the masked cell and match an unmasked backend on the other, and every output, i.e. everything that crosses back to EP, must equal the unmasked backend's exactly on both. A separate test pins `tension_kPa` as the backend's own `Function`, the one `post_solve` writes, not a copy.
- `test_monolithic_coupling.py` runs the coupling gates through a real one-element `pulse.StaticProblem`, quasistatic with a soft passive material so active stiffness exceeds passive — the regime R&Q show the naive segregated scheme is not convergent in. It judges a run unstable by the **onset of instability** — the first step after which the spread of λ over the element's quadrature points exceeds `1e-3` (or Newton fails) — rather than by when Newton gives up, which depends on solver settings the physics doesn't; the naive scheme's unstable mode is spatial, so `mean(λ)` alone hides it. Marked `@pytest.mark.slow`.
  - **S1** runs gate 1's inputs, regime and monolithic reference (dt 0.01 ms, 40 ms) under `stabilized`. It requires that the instability criterion never trips and that the error against the reference converges at first order at dt 1, 0.25 and 0.05 ms (orders ≥ 0.8; measured 0.83 and 0.97).
  - **Gate 4** (the zeta split's clean twitch at dt 1, 0.25 and 0.05) runs under `monolithic` and `stabilized`. Its naive control requires the `segregated` scheme on the same inputs to go unstable within 80 ms, and earlier as dt shrinks (measured onsets 20 / 15.75 / 7.7 ms). Without the control, gate 4 would not show that its regime is one the naive scheme fails in.
- `test_coupled_backend.py` pins the contract: `GeneratedActivation` and `CrossbridgeSegregated` satisfy `CoupledBackend`; `resolve` against a `GeneratedActivation` equals `resolve` against its module, for the zeta and Ca_i splits (not the third split, and not for `CrossbridgeSegregated`, which has no module and is covered by X1); the controller calls `begin_step`, the driver's `advance` and `post_solve` in that order with the times, over two steps, for both backends (through a recording driver); and an EP remainder keeping `lmbda` as a parameter, resolved against `CrossbridgeSegregated`, constructs and receives λ(u); and **X1**, that `CrossbridgeSegregated` resolves against the Ca_i split with forward `("cai",)` and backward `("J_TRPN",)`, and raises `ValueError` naming `Zetas` and `Zetaw` against the zeta split.
- `test_segregated_backend.py` drives `CrossbridgeSegregated` directly, now with `begin_step` then `post_solve` (`_drive`). `post_solve` is no longer a no-op: `test_post_solve_accepts_the_step` requires that after `begin_step` alone the model, `tension_kPa`, `stiffness_kPa`, `active_tension`, `J_TRPN` and `lmbda_prev` are unchanged while the trial has advanced, and that `post_solve` commits it (with `SL_ref` 2.0 against `SL0` 1.8, `stiffness_kPa` must equal `active_stiffness_to_mechanics` of the model's `Ka` bit for bit). `test_lambda_prev_is_the_stretch_the_ode_used` records the `SL` and `dSL` passed to `Land2017.advance_step` (patched on the class, so the deep-copied trial is seen) and compares them bit for bit with the accepted stretches in the backend's own order of operations, including after `u` moved before `begin_step`. The Review Focus tests pin the dt-0 rest state, `reset_stretch()`, the `RuntimeError` of `post_solve` without a pending step, a retry advancing from the accepted state, and the deprecated `step()`. **X3** (`test_failed_step_accepts_nothing`, slow) runs two converged controller steps on a one-element `StaticProblem`, then a solve that returns `False`, and requires the `RuntimeError` and bit-identity of every model array, `lmbda_prev`, `_lmbda_old`, `tension_kPa`, `stiffness_kPa`, `active_tension`, `outputs["J_TRPN"]` and EP's `missing_variables`. The controller's rollback discards the failed step's trial, so afterwards no step is pending and a stray `post_solve` raises. Its first step moves λ by only about 7e-9 (Land starts at TmB = 1), so a check that the retry, with the driver no longer failing, changes `CaTRPN` stands in for a large contraction.
- `test_crossbridge_coupling.py` holds the crossbridge gates, X4 to X6; X1 and X3 are above. The numbers are in its module docstring.
  - **X4** requires crossbridge's Land2017 (parameters from `land2017_from_ode`, initial states from `match_land2017_initial_states`) and the `.ode`'s generated Land to agree to first order in dt. They are two schemes for one model, so the gate is that the difference falls with dt, not that it is small. Measured maxima at whole ms over 60 ms, at dt 1 / 0.5 / 0.25 ms (orders): isometric, `|dTa|` 0.900 / 0.444 / 0.219 kPa (1.02, 1.02), 0.88 % of peak at dt 0.25, and `|dJ_TRPN|` 3.08e-4 / 1.56e-4 / 7.89e-5 mM/ms (0.98, 0.99); through the controller, mean tension 5.93e-2 / 2.20e-2 / 8.46e-3 kPa (1.43, 1.38), EP's mean `cai` 1.06e-5 / 5.18e-6 / 2.63e-6 mM (1.04, 0.98) and mean `J_TRPN` 2.51e-5 / 1.18e-5 / 5.90e-6 mM/ms (1.09, 0.99).
  - **X2** is gate 5 for every model in `crossbridge.MODEL_REGISTRY`, through `SimulationController` at dt_mech 1 ms. Max `|J_TRPN|` in EP after the first step / the last, mM/ms: RDQ18 5.45e-4 / 3.37e-6, Lewalle2024 4.11e-9 / 2.05e-5, Land2017 1.01e-4 / 7.75e-5, RDQ20MF 1.85e-3 / 1.80e-5 (crossbridge 0.3.3). Under 0.3.1 RDQ20MF failed X2's last assertion, that EP's states stay finite (cai was negative at 2.1 ms and NaN from 3 ms), and X2 marked it a strict xfail until 0.3.3 fixed `advance_step` (above).
  - **X5** is gate 1 and S1 for Land2017 on a one-element `StaticProblem`, under `stabilized`, with the naive control. The naive scheme goes unstable at 35.0 / 17.5 / 13.4 ms at dt 1 / 0.25 / 0.05 (Newton failed at 35.0 / 22.0 / 17.15 ms). Stabilized, the spread of λ stays at most 1.2e-15, and the max `|mean λ − reference|` is 1.13e-2 / 3.43e-3 / 7.67e-4 (orders 0.86, 0.93).

- **Checkpoint and rollback (§7).** The bit-for-bit gates compare everything `conftest._coupled_state` copies: every restart Function and metadata value of `controller.components()`, and EP's whole `parameters` and `missing_variables`. All run on pulse's default solver.
  - `test_checkpoint_backends.py` drives each backend directly (`register`/`begin_step`/`post_solve`, prescribed inputs, a displacement that changes between steps). A restore into a fresh backend continues bit for bit, `GeneratedActivation` under every scheme and `CrossbridgeSegregated` for every model in `crossbridge.MODEL_REGISTRY`. It also pins the names and metadata, `GeneratedActivation` states saved in another order and restored by name (and another set refused), the refusal of another backend's metadata, and a crossbridge `load_restart` discarding a pending trial.
  - `test_checkpoint.py` holds **R1** and **R3** on gate 5's harness (beat EP on the 3x3x3 cube, one element of mechanics, `dt_mech` 1 ms). **R1** runs 6 steps straight against 3, a checkpoint, every object built afresh, a restore and 3 more, and requires bit-identity both right after the restore (a difference there is the round trip through `restart.bp`) and at the end (one that appears only after stepping is state no component saves). A failure in a step's output (`results.bp` failing at 3 ms) writes no end checkpoint, and the restart from the 2 ms checkpoint gives the straight run's files.

The slab's and BiV's own tests cover the rest of `demo_io`.
- `test_biv_example.py` and `test_rodero_example.py` are cheap: no mesh, no case data (a fake case directory of the same layout stands in for physcardems'), no build, and builders that fail if called. They check that every option is physics or not, which options move the hash, the material as passed to pulse, the refusals before anything is built (a `--save-every` off the step, `--restart` with no checkpoint, a case with files missing), and each `summarise` on synthetic columns. The BiV's also checks that the circuit's `RR` is the period, i.e. HR goes in before flattening. `rodero_05`'s also checks that the case's resolved path and file contents move the hash and another path to the same case does not, that `summarise` works from `log.csv` alone, that a run whose `run.json` still says `running` is not reported converged, and that no quadrature point between endo and mid nodes is labelled epi.
- `test_ode_model.py` holds a strict xfail, `test_generated_state_order_does_not_depend_on_the_hash_seed`: gotranx 1.8.0 adds each assignment's dependencies to its `TopologicalSorter` in set order, so the generated state order depends on `PYTHONHASHSEED`. Restarts no longer depend on it (§7); remove the mark once gotranx sorts the dependencies. It has `raises=AssertionError`, and a crashed subprocess is a `pytest.fail`, so only differing orders satisfy it. `test_datacollector.py` now expects `DataCollector`'s `DeprecationWarning`.
- **Shared helpers in `conftest.py`.** `_run`, `_Run`, `_at_whole_ms`, `_lmbda_error`, `_observed_orders` and `_run_dynamic` moved there from `test_monolithic_coupling.py`/`test_dynamic_coupling.py`, with thresholds, dt and `t_end` unchanged, along with `_numpy_mech` and `_f0`. `caisplit_reference` is session-scoped there. `land2017_from_ode(mech_module)` maps the `.ode`'s Land parameters onto crossbridge's, and `match_land2017_initial_states` the initial states by name (CaTRPN←CaTrpn, B←TmB, S←XS, W←XW, Zs←Zetas, Zw←Zetaw, Cd←Cd). `_mechanics` and `_dynamic_mechanics` take `backend_factory(mesh, f0, quadrature_degree)` to build any `CoupledBackend`, and `_dynamic_mechanics` sets the end-of-step flag on the instance before building the problem. The gate loops call `backend.begin_step(t_n, dt)` after writing the inputs, instead of writing `backend.t`/`backend.dt`, which a crossbridge backend lacks; for `GeneratedActivation` that is the same two writes. `_crossbridge_factory(model, mech)` (moved from `test_crossbridge_coupling.py`) is the `backend_factory` for `CrossbridgeSegregated`. `_FailOnce(driver, at_step=n)` makes a driver advance and then report failure on its `n`-th step. `_coupled_state(controller)` copies everything a restore must reproduce, and `_assert_same_state` compares two such copies bit for bit.
- `test_transfer_plan.py` tests `resolve()` against the three shipped splits and `TransferPlan`'s construction guards and each direction on its own; `test_round_trip.py` (gate 5) is the one file whose tests run both directions together, through `SimulationController`, with real beat and pulse and nothing injected — a bug like the old MEF-zeros regression (mechanics → EP transferring nothing because the buffer it interpolated from was never written) shows up here as a flat array, not a false pass. Gate 5 runs under `monolithic` and `stabilized`, and the post-`step()` order test under all three schemes, each for the zeta and Ca_i splits. The same file pins the order inside `step()`: after one step, a second `plan.backward()` must leave EP's `missing_variables` and `parameters` bit-identical, which holds only if `post_solve` ran before `backward`.
- `test_averaging.py` tests `make_averager` against hand-computed lumped/cell averages.
- `test_coupled_system.py` exercises only `SimulationController`'s construction guards (quadrature-degree mismatch, backend identity, the `dt_mech`/`dt_ep` ratio, the EP ODE-solver type, and a `DynamicProblem`'s `dt` against `dt_mech`: a mismatch refused, a match accepted) against the same real `make_ep_solver`/`make_mechanics`/`make_dynamic_mechanics` fixtures as the gates above, on 1-cell meshes for speed — not a `DummyEPSolver`/`MockODEModel`, which no longer exist in this suite.
- `test_mechanics_drivers.py` checks three things. `as_driver` wraps a problem in `Solve` by its type, even one that has an `advance` attribute, passes a driver through, and refuses anything else. The controller advances through whichever driver it is given, with `(t_n, dt)` in ms, once per step. `Cycle` converts to pulse's seconds; the test uses a recording stub in place of `CycleController`, because a `dt` left in ms still converges and nothing else would notice.
- `test_dynamic_coupling.py` holds D1 and D2. Both drive the backend directly (`register`/`post_solve`, inputs prescribed) on `conftest._dynamic_mechanics`'s pinned element rather than through the controller. D1's reference backend is not `model.active`, so it could not pass the identity guard. The element is a 1 cm cube with `Compressible`, `Viscous` (η 100 Pa·s) and ρ 1e3. The regime is pinned because it decides what the gates can see: undamped, that cube rings (31–45 reversals of λ), and an unscaled 1 m cube is inertia-dominated.
  - **D1** requires the flagged backend to match `_TrueUActive` (§1, end-of-step evaluation) to `rtol=1e-10` in `mean(λ)`, and to differ from the α_f evaluation by more than `1e-3`. It asserts on λ because the stored states cannot show the difference: `post_solve` recomputes them at `u_{n+1}` either way, so only the equilibrium can.
  - **D2** requires the zeta split (the generated one, not `ZetaSplitUFL`) to twitch under `DynamicProblem` at dt 2, 1 and 0.5 ms, for 150 ms, under `monolithic` and `stabilized`, without diverging, going non-finite or losing its damping (at most 2 reversals of λ). Its inputs are `D2_INPUT_SCALE` = 10 times gate 4's, which puts `Ka_max` at 464–495 kPa. That is above what the element supplies at dt 2 and 1 ms, η/dt + ρL²/dt² = 75 and 200 kPa, but not at dt 0.5 ms, where it supplies 600 kPa: 200 of damping (η/dt) and 400 of inertia (ρL²/dt²). At ×1 every scheme gave 1 reversal at every dt, the damping hid the instability, and D2 passed under the naive scheme too. At ×10 its naive control (`test_naive_scheme_oscillates_in_the_d2_regime`) requires the `segregated` scheme to fail or exceed 2 reversals at dt 2 and 1 (measured: a failure at 34 ms at dt 2, 29 reversals at dt 1). At dt 0.5 the naive scheme is clean, because 600 kPa exceeds `Ka_max`, which is recorded and not asserted. D2 therefore discriminates the period-2 instability at dt 2 and 1 ms. D1 remains the gate that tells end-of-step from α_f apart; D2 was not checked for that.
- `test_circulation.py` holds Stage A's gates. They run on `conftest._ellipsoid_ep_mechanics(circulation=True)`: the zeta split on `lv_ellipsoid`, ENDO coupled to Regazzoni's LV, ToR-ORd firing everywhere at `t = 0`, and the circuit started from the unloaded cavity volume. Each run is 20 steps of 2 ms through `CirculationClock`. All are `@pytest.mark.slow`.
  - **A1** requires the total blood volume to be conserved to `rtol=1e-8`, with the deformed cavity's `V(u)` in place of the circuit's `V_LV` state. Summed over the circuit's own states the total is linear, and backward Euler conserves a linear invariant whatever the mechanics does. Only with `V(u)` does drift detect a coupling error, and a 0.1% coupling error fails at 1.1e-4.
  - **A2** requires the LV pressure to be strictly above that of the same run with `tension_scale = Constant(0)`, wherever mean `Ta > 0.01` kPa.
  - The clock test checks `CirculationClock`'s units and guards, with `solve` replaced by a recorder.
  - `test_ellipsoid_builder_refuses_circulation_with_cycle` requires `_ellipsoid_ep_mechanics` to refuse `circulation=True` with `cycle=True` (`ValueError`), before it builds anything: ENDO is either a chamber of the circuit or a controlled cavity.
  - The fibre check is described below.
- `test_cycle_coupling.py` holds Stage B's gates on `_ellipsoid_ep_mechanics(cycle=True)`, both `@pytest.mark.slow`.
  - **B2** runs one EP-driven beat with em_tref7's LV cycle and `Tref` (840 kPa), and ToR-ORd's stimulus moved to the end of diastole (120 ms). It requires PRELOAD → IVC → EJECTION → IVR → FILLING in order, with V constant over the IVC and IVR steps (`rtol=1e-6`). Each step is labelled by the phase read before it. Newton gets 150 iterations (`CYCLE_SNES_MAX_IT`): pulse's own cycle gate on this ellipsoid needed 72 on one isovolumic-relaxation step. That number is an iteration budget, not a tolerance.
  - **Review Focus 1** makes a step infeasible: one Newton iteration to reach half the volume in IVC. It requires `RuntimeError` from the controller, with nothing accepted: backend states, λ, outputs, `active_tension`, EP's arrays, `u` and the cavity pressure must all be bit-identical. A converged step runs first, so a rollback that zeroed the states would not pass.
- A1, A2 and B2 are integration gates, not pins on the backend's dynamics. The final review's mutants showed that they pass under the α_f evaluation (`evaluate_at_end_of_step = False`), and that they still pass with the backend's GRL step frozen (the controller holding `backend.dt` at 0). The backend's dynamics under `DynamicProblem` are pinned by D1, D2 and the static gates, and D2 pins the scheme (monolithic and stabilized clean; the naive control is asserted at dt 2 and 1, and at dt 0.5 the naive scheme is clean, recorded and not asserted) but not the end-of-step evaluation, which only D1 pins.
- `test_rodero_case.py` has four tests. Review Focus 5 requires a case directory with files missing to raise `FileNotFoundError` naming every one, before io4dolfinx is reached. Another checks the loaded case against physcardems' numbers, and is skipped unless `third-party/physcardems/cases/rodero_05` exists, so CI skips it. It covers the cell counts, the 0.9³ volume scaling, closed LV/RV cavities (by origin-shift invariance, §4), unit DG0 fibres, the mask and stiffness fields, the LAT range and the Land values. The other two are about the pseudo-ECG's electrodes, which only `post.py` reads, so they are not among the files a case must have. One requires a missing electrode file to be reported by name when it is read. The other, skipped without the case, requires the electrodes in physcardems' order (LA, RA, LL, RL, V1–V6), converted from cm to m.
- **`conftest.lv_ellipsoid`** is module-scoped: pulse's coupling-test ellipsoid in metres, with analytic fibres on `Quadrature_2`, the geometry's and the backend's own degree. `_ellipsoid_ep_mechanics` refuses any other `quadrature_degree`. The fibres are on quadrature because a field that is unit length at the nodes is not unit length between them (ruling R25). P1 fibres on this mesh, whose fibre angle turns through 120° across a wall about one element thick, are 0.32–0.95 long at the quadrature points (mean 0.82). λ at rest was then about 0.82, Land's length dependence was cut off, and Holzapfel-Ogden's fibre term, which acts only for `f0·C f0 > 1`, stayed off until the true stretch passed about 1.22. B2 failed to fill with nothing wrong in the code it tested. Fibres computed at the points they are read at are unit length exactly, which `test_lv_ellipsoid_fibres_are_unit_where_they_are_read` asserts. The degree is not pulse's 6 because FFCx requires every quadrature-element coefficient of an integral to share its points, so fibres at 6 beside states at 2 do not compile. Check any new geometry the same way. `rodero_05`'s DG0 fibres are asserted unit per cell in `test_rodero_case.py`, and `circulation_biv` uses `Quadrature_6` at degree 6.
- `test_isolated_ep.py` builds a minimal synthetic `.ode` file on the fly (via `load_ode_modules`) to check the generated EP module's own mechano-electric feedback (`missing_variables` reaching the RHS), independent of any coupling machinery.
- `test_isolated_mechanics.py` / `test_stability.py` exercise `ZetaSplitUFL` directly against `pulse.StaticProblem`.

`test_backends.py` carries the equivalence record for the port: it writes out, by hand, the stress form that the deleted `MechanicsProblem._material_form` built, and requires `ZetaSplitUFL` to reproduce it. Since that form no longer exists in the package, the test is the only remaining copy of it — don't delete it when adding backends. It also pins `ZetaSplitUFL.evaluate_at_end_of_step is True`, on the class and an instance: pulse's `ActiveModel` defaults the flag to `False`, and before this test nothing failed when the line was deleted.
